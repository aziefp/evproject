# 第一阶段需求基线

更新时间：2026-09-05

## 1. 目标与边界

第一阶段交付三个可运行部分：

1. Linux + Qt 充电用户端。
2. Linux + Qt PC 管理服务器端。
3. 与服务器部署在同一台电脑上的 SQLite 数据库。

正式演示目标为用户端和服务器端运行在两台电脑上，通过局域网 Socket 通信；开发和课堂演示必须同时支持在同一台电脑上通过 `127.0.0.1` 启动。

大数据 Web 可视化和机器学习属于第二阶段，本阶段不实现，但数据库必须保留第二阶段可用的订单事实数据。

## 2. 优先级定义

- **P0**：说明书明确要求或主业务闭环不可缺少；全部通过才算第一阶段完成。
- **P1**：原版截图体现、能明显提高完整性且成本较低；P0 完成后实施。
- **P2**：加分项或成熟产品常见功能；本阶段默认不做。

## 5. 数据、通信与错误处理

| ID | 优先级 | 需求与验收要点 |
|---|---|---|
| SYS-01 | P0 | 用户端不直接连接 SQLite；所有业务写入由服务器完成。 |
| SYS-02 | P0 | TCP 协议可正确处理粘包、半包、非法长度、超时和未知消息类型。 |
| SYS-03 | P0 | 预约/开始和结算使用数据库事务，防止一桩多占、重复订单和重复扣费。 |
| SYS-04 | P0 | SQLite 开启外键；写操作由数据库工作线程串行执行；程序退出和重启后数据保持。 |
| SYS-05 | P0 | 参数错误、余额不足、冻结、桩占用、网络失败、地图失败和数据库失败均给出可理解提示。 |
| SYS-06 | P0 | 使用参数化 SQL、带盐密码摘要、会话令牌、消息长度限制和图片大小限制。 |
| SYS-07 | P0 | 主框架为多线程；GUI、网络 I/O、数据库和充电模拟不相互阻塞。 |

## 6. 明确不做的内容

- 第二阶段 Web 大屏、数据平台和机器学习模型。
- 真实 GPS、真实充电桩协议、真实短信验证和真实支付。
- 扫码、优惠券、会员、社区、评价、停车费、车辆管理、跨运营商聚合。
- 高可用数据库集群、互联网公网部署和生产级账户安全体系。

## 7. 成熟产品参考的取舍

特来电、星星充电和 e 充电等产品共同强调找桩、站点状态/价格、导航、开始充电、订单/账单等主链路。本项目只借鉴这些信息层级和交互顺序，不复制品牌视觉，也不引入营销功能。

本阶段采用的界面原则：

- 用户端默认为竖屏手机尺寸，用卡片、底部导航和可单手操作的按钮完成主流程。
- 首页优先显示距离、价格、空闲桩和站点状态。
- 站点详情把“预约充电”和导航作为最明显操作。
- 充电页始终显示时长、电量、当前费用和停止按钮。
- 管理端的查看、重启、结算、冻结等操作以行内按钮对应到具体数据，不依赖隐藏的双击行为。
- 错误状态说明原因，并提供唯一明确的恢复动作。
