# 测试与完成定义

更新时间：2026-09-08

## 1. 实施顺序

第一阶段基础系统已按以下顺序完成：环境与外部服务 → 公共协议和工程骨架 → SQLite 与管理基础 → 用户找站/资料 → 充电交易 → 管理统计/地图 → 系统验证。第二阶段及产品化优化继续保持未开始，避免偏离验收重点。

后续若发现缺陷，优先修复会破坏主业务、数据一致性、两端协议和演示稳定性的问题；视觉细节和额外功能排在全部验收项之后。

## 2. 已执行自动化验证

`ctest` 当前包含：

- `protocol`：单帧往返、半包、连续多帧、非法长度和非法 JSON。
- `database`：新用户默认资料、充值、距离升序、双用户抢桩、活动订单约束、预约—开始—计量—停止—结算、充电进度与充满自动停止、重复结算、余额耗尽自动停止、订单记录与状态筛选、管理员登录、电站新增、统计、电桩状态筛选、安全故障上报与完整重启状态、冻结/解冻和数据库重启持久化。

`scripts/integration_smoke.py` 连接真实 `ev-admin-server`，验证登录、重复请求不重复充值、腾讯地址解析、电站/电桩、完整订单、服务端定时计量、历史记录、退出后旧令牌失效与同连接重新登录，以及同一账号两个客户端之间的订单/站点推送。两个 GUI 可执行程序的启动存活检查也已通过。

## 4. 交付前手工检查

在课堂演示电脑上只需做一次短检查：

1. 运行 `./run-demo.sh`，管理端以 `admin / 123456` 登录。
2. 用户端登录，定位、查看电站和两种导航页面。
3. 用新手机号充值，选择空闲桩完成一笔订单；观察管理总览同步变化。
4. 在管理端按状态筛选订单，将一个空闲桩报告为故障并远程重启，再冻结/解冻用户。
5. 按 `docs/08-build-test-run.md` 第 4 节完成两台物理电脑的 LAN 联调，重复一笔订单并重启服务器核对持久化。

基础系统完成的判定是：上述功能无阻塞缺陷、自动化测试通过、物理环境中两端能启动。答辩截图、安装包、界面美化和第二阶段功能不属于当前基础实现完成条件。
