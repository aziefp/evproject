## 3. 生效决定

- **范围**：开发代理承担端到端实现；所有第一阶段基本验收优先于加分项，第二阶段明确隔离。
- **部署**：正式目标为 LAN 两机，localhost 是必备调试/演示模式，两者走同一协议和代码路径。
- **技术栈**：Qt 6.11.2 GCC 64-bit、Qt Widgets、C++17、CMake、QTcpSocket/QTcpServer、SQLite、Qt Charts、QWebEngineView。
- **线程**：管理 GUI 在主线程；服务器网络、数据库、地图请求和模拟计量由一个独立 Qt 工作线程串行拥有，满足多线程且避免跨线程数据库连接。
- **协议**：4 字节大端长度 + UTF-8 JSON；会话令牌、1 MiB 限制、心跳/超时、重连和同连接请求 ID 去重。
- **一致性**：金额存整数分、电量存整数 Wh；SQLite 外键、事务和活动订单部分唯一索引维护用户/电桩约束。
- **充满目标**：基础版不建模真实车型电池，每笔订单统一以 20 kWh 作为可快速验收的演示目标；判定和封顶均在服务器执行。
- **地图**：服务器调用腾讯地址解析；用户端以 QWebEngineView 加载 URI 驾车/步行路线。Key 仅从被忽略的本地文件读取。
- **界面**：用户端保持 420×720 竖屏移动布局，地图请求移动端页面；管理端列表的数据级操作使用显式行内按钮。
- **图形兼容**：只对 VMware + Wayland 自动启用 XCB 与 WebEngine 软件合成；其他机器保持默认，环境变量可显式覆盖。
- **同步**：服务端数据是唯一真相；计量事件做轻量局部更新，业务状态变化用事件通知各会话重新查询，避免高频全量刷新和界面跳转。
- **数据**：6 站、32 桩、8 用户、60 笔历史订单及活动/故障场景，规模只服务于课堂展示。
- **文档**：只维护范围、架构、协议、数据、部署、验收和关键状态；直接修订并清理过时内容，不记录过程流水。

## 4. 已知边界

- 手机登录、充值、定位、充电桩和支付均为课程模拟，不接真实短信、GPS、支付或硬件协议。
- 头像以压缩 Base64 存 SQLite，适合少量演示数据，不是生产设计。
- 请求 ID 去重缓存以当前连接为范围；订单结算另有数据库级幂等。当前客户端不会自动重发普通业务写请求。
- 物理两机连接、防火墙和目标电脑运行库必须在设备可用后现场确认；代码已支持监听地址、端口和服务器 IP 参数。
- 管理订单页已支持列表和待结算代处理，但还没有截图衍生的 P1 状态/时间筛选；这不是原版功能文字的 P0 项。
- 服务器使用 Qt `QThread` 工作线程，没有直接调用 `pthread` API；若课程对“pthread”按源码 API 而不是 Linux 原生多线程效果验收，需向老师确认口径。
- 腾讯地图地址解析已处理网络错误和服务错误，但尚未设置应用层硬超时；这是最值得在最终稳定性轮次修补的点。
